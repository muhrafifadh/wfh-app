# 01 · Project Structure

## Layout

```
├── prisma/
│   ├── schema.prisma
│   ├── migrations/            # Generated by Prisma; never edit one after it's applied
│   └── seed.ts                # Seed data for development and tests
├── prisma.config.ts
├── src/
│   ├── main.ts                # Bootstrap: create the app, configureApp(), listen
│   ├── configure-app.ts       # Global prefix, helmet, CORS, body limit, Swagger, shutdown hooks (shared with e2e)
│   ├── app.module.ts          # Root module: imports config, infra, modules; registers global providers
│   ├── config/
│   │   ├── env.ts             # Zod schema for env vars
│   │   └── config.module.ts
│   ├── common/                # Shared code that isn't about any domain
│   │   ├── decorators/        # @Public, @Authenticated, @RequirePermissions, @CurrentUser
│   │   ├── guards/            # RouteAuthAuditor (auth guards live in modules/auth/guards)
│   │   ├── types/             # AuthUser, Permission, Express request typing
│   │   ├── filters/           # AllExceptionsFilter
│   │   ├── errors/            # AppError + generic subclasses
│   │   ├── dto/               # Pagination query/response, shared DTOs
│   │   └── utils/
│   ├── infra/                 # Clients for external systems
│   │   ├── prisma/            # PrismaModule, PrismaService
│   │   ├── health/            # /health endpoints
│   │   ├── mail/                # MailService: console (dev) / memory (tests) / disabled
│   │   └── queue/
│   ├── modules/               # Domain modules, one per area of the business
│   │   ├── auth/
│   │   ├── users/
│   │   └── invoices/
│   │       ├── dto/
│   │       │   ├── create-invoice.dto.ts
│   │       │   ├── update-invoice.dto.ts
│   │       │   ├── list-invoices.query.ts
│   │       │   └── invoice.response.ts
│   │       ├── jobs/          # Queue processors (if any)
│   │       ├── invoices.module.ts
│   │       ├── invoices.controller.ts
│   │       ├── invoices.service.ts
│   │       ├── invoices.service.spec.ts
│   │       ├── invoices.repository.ts
│   │       ├── invoices.errors.ts
│   │       └── invoices.constants.ts
│   └── generated/prisma/      # Prisma client output (gitignored)
├── test/                      # E2E tests + setup
│   ├── setup.ts
│   └── invoices.e2e-spec.ts
├── docker-compose.yml         # Postgres (+ Redis) for local dev and tests
└── .env.example
```

## Rules

- **One module per business domain** (`invoices`, `customers`), not per technical layer. Don't create `controllers/` or `services/` folders at the top level.
- **Imports only flow one way:**

  ```
  modules  →  infra, common, config
  infra    →  common, config
  common   →  config (nothing else)
  ```

  `common/` and `infra/` never import from `modules/`.

- **Modules use other modules only through their exported service.** `InvoicesModule` imports `CustomersModule` and injects `CustomersService`. It never imports `customers.repository.ts` or reads the `customers` table itself.
- **No circular module dependencies.** If two modules need each other, move the shared logic into a third module, or communicate with events ([15](15-background-jobs.md)). Don't use `forwardRef` (except in third-party code you can't change).
- **A module only creates the files it needs.** A module with no jobs doesn't need a `jobs/` folder.
- **Don't add barrel files (`index.ts`)** inside `modules/`. They cause circular imports and hide where things come from.
- **`src/generated/` is gitignored** and rebuilt by `prisma generate` (which runs on `postinstall`).

## Don't

- **Don't add a `shared/` or `helpers/` module that collects random code.** Domain code that several modules need belongs in its own module. Code that has nothing to do with the domain goes in `common/`.
- **Don't put domain logic in `common/`.** If the code mentions an invoice, it belongs in `modules/invoices`.
- **Don't add top-level folders** that aren't listed above without updating this doc first.
